# HydraCup v0.6.0

## 主要更新：OTA 韌體更新

- 設定頁新增「08 韌體更新」卡片，可直接從 GitHub Releases 檢查版本並更新韌體，完成後自動重新開機。
- 新增 `lib/OtaUpdater/`：專屬 `ota_worker` task（10 KB static stack、優先權 3、pin core 0），以 `esp_https_ota` 寫入備用 app slot。下載期間 Web UI 仍可正常查詢進度。
- 新增 `GET /api/ota/status`、`POST /api/ota/check`、`POST /api/ota/update` 三個端點，沿用既有的登入 session 與 CSRF 保護。
- 版本檢查讀取 release 的 `version.txt` 固定資產，而非 `api.github.com`：後者未認證時限 60 req/hr/IP，家用 NAT 下多台裝置會撞牆，且需要 8 KB 靜態 buffer 解析 JSON。SemVer 比對為**嚴格大於**，遠端版本較舊時不會觸發更新。
- 啟用 bootloader rollback（`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE`）。新韌體須在控制任務持續心跳滿 30 秒後才確認為 valid，否則下次開機自動回滾到前一個 slot。
- 確認條件**只看 uptime 與控制任務心跳，不含 WiFi**。未設定 WiFi 的裝置走 AP Mode，若把連線納入條件會導致每次開機都被回滾。

## 韌體體積最佳化

原本 `firmware.bin` 已佔 1.25 MB app slot 的 90.0%（1,179,312 B），沒有空間容納 OTA。本版改用
size 最佳化並移除未使用的 C++ 執行期機制：

| 變更 | 節省 |
|---|---|
| `CONFIG_COMPILER_OPTIMIZATION_SIZE`（`-Og` → `-Os`） | 98,672 B |
| `CONFIG_COMPILER_CXX_EXCEPTIONS=n` / `CXX_RTTI=n`（全專案零 `try`/`catch`、零 `dynamic_cast`/`typeid`；`virtual` 不受影響） | 47,664 B |

加入 OTA 後 `firmware.bin` 為 1,067,910 B（**81.5%**），較改版前多出約 240 KB 餘裕。
分割區表未變動，`logfs` 飲水紀錄不受影響。

新增 `[env:esp32dev-debug]`，以 `-Og` 建置同一份韌體供 GDB 使用；發佈與 OTA 映像一律來自
`esp32dev`。CI 與 release workflow 都會擋下超過 app slot 92% 的韌體。

## 併發降載

`esp_ota_write()` 期間兩顆 core 的 flash cache 會被反覆停用，因此更新時：

- **暫停飲水事件判定**——HX711 是時序敏感的 bit-bang，此時讀值會失真，寧可漏記也不要把假事件寫進 logfs 與雲端。秤重取樣本身不停，Web 的即時重量顯示照常。
- **暫停 Cloud sync 與 Discord**——各自的 mbedtls session 約 40 KB heap，與韌體寫入直接競爭。事件留在佇列中，更新結束或失敗後自動排出。
- **暫停 MQTT 心跳**——節省 socket 預算。
- 更新前檢查內部可用 heap，低於 60 KB 直接回 `503 insufficient_memory`；寫入途中 OOM 會留下半寫入的 slot，事前拒絕更安全。

`CONFIG_LWIP_MAX_SOCKETS` 由 10 提高到 16，並將 httpd 的 `max_open_sockets` 顯式設為 5——
GitHub 會 302 轉址到 `objects.githubusercontent.com`，下載期間需要 2–3 條連線，原本的預算不夠。

## 憑證信任

OTA 改用 ESP-IDF 內建 CA bundle 的 CMN 子集（41 張、約 18 KB），**不釘選根憑證**。GitHub 的
release 轉址跨兩個網域且憑證鏈自行輪換，釘選一旦失效就等於同時失去發佈修正的能力。
`CloudSyncClient` 與 `DiscordNotifier` 維持既有的釘選 PEM。

## 升級與相容性

**本版必須以 USB 燒錄一次，之後才能使用 OTA。** rollback 是 bootloader 的行為，只有重燒
bootloader 才會生效：

```powershell
pio run -e esp32dev --target upload     # bootloader + partitions + otadata + firmware
pio run -e esp32dev --target uploadfs   # webfs（設定頁的韌體更新卡片）
```

`uploadfs` 只更新 `webfs`，不會清除 `logfs` 飲水月檔，也不需清除 NVS。

**OTA 不會更新 `webfs`。** 日後設定頁改版仍需 `uploadfs`。為此 `/api/ota/status` 的 JSON 欄位
只增不改，且所有面向使用者的文字都由韌體回傳、前端只做渲染，讓舊版 UI 也能顯示新韌體的
狀態與錯誤。

完整操作見 [Build & Flash](../guides/build-flash.md)。

## 驗證

- `pio run -e esp32dev`
- `pio run -e esp32dev-debug`
- `pio test -e native`
- `pio run -e esp32dev --target buildfs`

尚未在實機驗證的項目見本版 PR 說明：`-Os` 對 HX711 bit-bang 時序的長時間影響、完整
OTA 端到端流程，以及刻意推送壞韌體的 rollback 驗證。
