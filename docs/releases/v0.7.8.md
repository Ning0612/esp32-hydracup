# HydraCup v0.7.8

## 只有版本號，沒有功能變更

本版存在的唯一目的，是讓 v0.7.7 的 IRAM 緩衝區修正有機會以「執行端」的身分運作一次。

OTA 下載由裝置上**原本**的韌體執行，不是被下載的那一份。因此修正必須等裝置先跑到含有它的
版本，再更新到下一版才會生效。裝置更新到 v0.7.7 之後，本版就是它的第一次執行——也是
webfs OTA 自 v0.7.0 引入以來，第一次有機會真正把網頁資源寫進分割區。

只升版本號是為了只留一個變因：成功即可歸因於 `MALLOC_CAP_8BIT`，失敗則由 v0.7.6 加入的
步驟 log 與 v0.7.3 的更新結果保存指出下一層問題。

## 這一串問題的完整軌跡

| 版本 | 修正 | 是否為 webfs 從未成功的原因 |
|---|---|---|
| v0.7.2 | 下載跟隨轉址 | 不是主因，但**必要**——沒有它下載不會開始，後面的問題都碰不到 |
| v0.7.4 | 邊抹邊寫取代整片抹除 | 不是主因，但**有價值**——讓崩潰不再留下被抹空的分割區 |
| v0.7.6 | OTA task stack 10→16 KB | **不是**。當時推測為 stack 溢位，實際不是；16 KB 保留為餘裕 |
| v0.7.7 | 緩衝區改用 `MALLOC_CAP_8BIT` | **是**。`MALLOC_CAP_INTERNAL` 也可能配到 IRAM，而 IRAM 只允許 32-bit 對齊存取，memcpy 第一批資料時即 panic |

真正的原因由 serial 擷取到的暫存器 dump 直接指出：`LoadStoreError`、出錯位址在 IRAM、
長度 4096 正是 `OTA_WEBFS_CHUNK`、PC 在 ROM memcpy。
