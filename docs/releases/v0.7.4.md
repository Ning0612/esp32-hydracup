# HydraCup v0.7.4

## 修正：webfs 寫入前的整片抹除會拖垮下載連線

v0.7.3 的更新中，webfs 的轉址問題已修好、下載也確實開始了，但重開機後 webfs 掛載失敗
（`Corrupted dir pair`），裝置只剩「Web assets unavailable」。

把分割區 dump 出來比對，答案很直接：**384 KB 全部是 `0xFF`——抹除成功了，但一個位元組都
沒有寫進去**。耗時約 30 秒，正是讀取逾時（15 秒）的量級。

**原因**：流程是「開啟 HTTP 連線 → 抹除整個 384 KB 分割區 → 開始讀取」。整片抹除是數秒等級
的操作，而且每次抹除都會停用兩顆 core 的 flash cache；lwIP 執行於 flash，這段期間 TCP/TLS
連線等同無人服務。等抹除結束回頭要讀，連線已經失效，`esp_http_client_read()` 一路逾時到放棄。

**修正**：改為**邊抹邊寫**——每寫入一個 4 KB 區塊前才抹除該區塊，讓連線持續有資料流動。
單次 4 KB 抹除是毫秒等級，不會中斷連線。這也正是 `esp_ota_write()` 內部採用的做法。
下載完成後才把映像之後的殘餘區域一次抹掉，此時已無連線需要維持。

## 為什麼前幾版沒發現

這一系列問題有個共同結構：**OTA 的修正只能由下一次更新來驗證**，因為執行下載的永遠是舊韌體。

- v0.7.2 修好轉址，但那次更新由未修正的 v0.7.1 執行，修正沒有機會跑
- v0.7.3 由已修正的 v0.7.2 執行，轉址修正確實生效、下載真的開始了——才因此暴露出下一層的
  抹除問題

本版同理，需要由 v0.7.3 執行更新才能驗證。

## 驗證

- `pio run -e esp32dev`
- `pio test -e native`
- 損毀分割區的 dump 已與預期映像逐位元組比對，確認為「已抹除、未寫入」
