# HydraCup v0.5.0

## 主要更新：杯況感知提醒與 LINE／LIFF 整合

- 提醒只在水杯穩定放置後開始或繼續倒數；杯子拿走時保留剩餘時間。
- 有效喝水事件會重新開始完整提醒週期；補水與不符合飲水量門檻的重量變化不會重設提醒。
- Local Device Console 與 LIFF 採用一致的飲水進度、水滴、漣漪、滿杯與溢水視覺語言，並支援亮暗主題與 `prefers-reduced-motion`。
- 點擊、觸碰或以鍵盤啟用進度水杯只播放晃水與摘要互動，不會新增或修改飲水紀錄。

## Cloud sync、配對與歷史補傳

- 新增 `CloudSyncClient`，以 LittleFS durable outbox 保存已確認的飲水／補水事件；server ACK 前會持續重送，並以 NVS emergency overflow 處理短暫 outbox append 失敗。
- 裝置使用 NVS 產生的 256-bit raw token，Local WebUI 只顯示 Device ID 與 token SHA-256；raw token 不進瀏覽器、Cloudflare secrets、文件或 Git。
- 第一次成功同步且尚未綁定時，Device Console 顯示 8 碼、10 分鐘有效的 LIFF 配對碼；配對完成後由後續同步清除。
- 設定頁可啟動可恢復的歷史補傳，逐月將今天以前的 Local 每日摘要送到 service；server 逐日取事件 aggregate 與裝置快照的最大值，重跑不會重複累加。
- 歷史補傳游標綁定 service origin、Device ID 與 token identity；身分變更後會從頭安全重送。

## Local 與 LIFF 使用體驗

- Local History 與 LIFF 趨勢熱力圖預設顯示最近 365 天，並可切換指定完整年份；平年顯示 365 格、閏年顯示 366 格。
- Local History 直接讀取 LittleFS 月檔；LIFF 讀取已同步事件及歷史補傳快照。啟用 Cloud sync 後需保持 `UTC+8`，讓即時事件、Local 月檔與 service 的 Asia/Taipei 日期邊界一致。
- ESP32 仍是飲水事件、重量與提醒狀態的唯一真實來源；Web／LIFF 不提供手動新增飲水量。

## 升級與相容性

1. 先部署支援 protocol v1 與 `device_history_days` migration 的 `hydracup-service`。
2. 建置並燒錄 firmware，再以 `uploadfs` 更新 Local WebUI；不要執行整片 erase。
3. 登入 Device Console，確認 Cloud sync 的 Service URL、`UTC+8`、Device ID 與 token SHA-256 allowlist。
4. 等待 HTTP `200` 並完成 LIFF 配對；需要既有 Local 歷史時，再由設定頁手動啟動補傳。

`uploadfs` 只更新 `webfs`，不會清除 `logfs` 飲水月檔；一般 firmware／webfs 升級也不需清除
NVS。完整操作見 [Build & Flash](../guides/build-flash.md)、[Configuration](../guides/configuration.md)
與 [HydraCup Service 使用指南](https://github.com/Ning0612/hydracup-service/blob/main/docs/user-guide.md)。
