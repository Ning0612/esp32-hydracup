# HydraCup v0.7.2

## 修正：webfs OTA 因未處理轉址而必定失敗

v0.7.0 加入的網頁資源 OTA 從來沒有成功過。實機更新到 v0.7.1 時，韌體正常寫入，但狀態顯示
「網頁資源更新失敗」。

**原因**：`esp_http_client` 只在 `esp_http_client_perform()` 的狀態機裡處理 301/302
（`esp_http_check_response()`）。webfs 因為要邊下載邊寫入分割區，走的是低階的
`esp_http_client_open()` / `fetch_headers()` / `read()` 串流流程，**這條路徑不會跟隨轉址**，
GitHub 的 302 會原封不動回傳。程式看到狀態碼 302 不在 2xx 範圍就直接放棄。

韌體那一半沒有受影響，是因為 `esp_https_ota` 內部走的是會處理轉址的路徑。

**這個失敗是安全的**：放棄發生在卸載與抹除分割區**之前**，webfs 一個位元組都沒被動到，
裝置全程可用。

**修正**：`_updateWebfs()` 自行跟隨轉址（最多 `OTA_MAX_REDIRECTS` 次），每次以
`esp_http_client_set_redirection()` 取得新位址後重新開啟連線。

## 失敗訊息不再被通用文字蓋掉

先前 webfs 失敗時，最終狀態一律顯示「網頁資源更新失敗，需以 USB 重新燒錄」，把
`_updateWebfs()` 記錄的具體原因蓋掉了——既看不出是哪一步失敗，也在分割區根本沒被觸碰時
錯誤地要求使用者重新燒錄。現在會保留具體原因，例如「網頁資源下載失敗（HTTP 302）」。

## 升級

可直接由設定頁「08 韌體更新」以 OTA 更新。本版是第一個網頁資源真的會隨 OTA 更新的版本。

## 驗證

- `pio run -e esp32dev`
- `pio test -e native`

轉址修正尚未在實機驗證——這正是本版要驗證的事。
